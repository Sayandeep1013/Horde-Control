# Feel pass (2026-10-06)

Owner: game-feel fixes for the JANK items J1 to J9 of `2026-10-06_ART_AND_FEEL_REVIEW.md`. Decisions D151 to D155 in `MASTER_SDLC.md`. Machine: GTX 1650 Ti, 144 Hz display, Godot 4.7.1.

## Changes

| Item | Change |
|---|---|
| J1 | `project.godot`: `physics/common/physics_interpolation=true`, `physics_jitter_fix=0.0`. SimLoop already steps inside `_physics_process` (`sim_loop.gd:179`), so every mover (Player, enemies, projectiles, pickups) moves in physics ticks and interpolation applies with no change to that path. Register "Physics" row and docs/20 pinned settings updated. |
| J2 | `GameCamera` moved from `Main/Player` to `Main` (target `../Player`). It sets `physics_interpolation_mode` OFF in `_init` (before entering the tree, otherwise `Camera2D` overrides itself to its physics callback) and forces `process_callback` IDLE. Godot 4.7 has **no** `get_global_transform_interpolated()` for 2D nodes (`CharacterBody2D` rejects the call), so the camera samples the target in `_physics_process` at physics priority 100000 (after every mover) and lerps previous tick to current tick by `Engine.get_physics_interpolation_fraction()`. While the tree is paused it uses the plain position. Lead now comes from `CharacterBody2D.velocity`. All `Main/Player/GameCamera` paths were updated (`prototype.tscn`, `prototype_integration.gd`, `ui_capture.gd`, four tests). |
| J3 | `reset_physics_interpolation()` after both `wave_director.gd` spawn placements, `PlayerProjectile.launch`, `TowerProjectile.launch`, `Pickup.configure`, and the `--player_pos` capture teleport. Damage-number labels and sheep set interpolation OFF (tween or `_process` driven). The pickup sprite bob and the telegraph pulse moved into `_physics_process` so they stay inside the interpolated parent transform (OFF on a child of a moving parent would step it at the tick rate). Health and overhead bars only redraw in place, so they need nothing. |
| J4 | `enemy_animator.gd`: flip needs a horizontal share above 0.35 and 0.2 s since the last flip; strike clips keep their own flip. |
| J5/J6 | `player_animator.gd`: moving cancels any holding shoot pose and `play_shoot()` is a no-op while moving; stretch and lean exports default to 0. |
| J8 | `game_camera.gd`: `FastNoiseLite` sampled at 30 Hz by time, trauma squared, same 12 px cap, still before the arena clamp. |
| J9 | Draft root fades in and out over 0.15 s (gameplay state changes at once); collected pickups leave a swell-and-fade ghost. Both skipped under the headless display driver. Pause menu, run end and menu cards already tween through `menu_frame.gd`. |

## Tests

Added: `game_camera_follow_test.gd` (interpolation off, lead from velocity with a static position, no backward step between ticks), `enemy_facing_hysteresis_test.gd` (near-vertical heading, clear reversal, per-frame oscillation), three run/shoot tests and a no-squash-no-lean test in `player_animation_test.gd`, camera sibling and interpolation-off assertions in `prototype_scene_test.gd`. The squash and lean tests now opt in by setting the exports.

Targeted runs, all assertions green: `game_camera_follow_test` 3, `camera_bounds_test` 7, `game_camera_shake_gate_test` 3, `enemy_facing_hysteresis_test` 3, `player_animation_test`, `prototype_scene_test` 33, `feel_hooks_test` 5, `ui_capture_seams_test` 2, `pickup_physics_test` 11, `pickup_merge_cap_test` 5, `draft_input_lockout_test` 11, `draft_explains_itself_test` 6, `damage_number_fx_gate_test` 3, `arena_scene_test` 4. Any suite that instantiates the real Player or prototype scene also ends with the harness's "100 resources still in use at exit" engine error, which makes `run_tests.ps1` report NOT A USABLE RUN. That error also occurs on the untouched baseline commit (checked with `entity_visual_test`), so it is not from this pass. Once, `game_camera_follow_test` exited with a native crash at shutdown while it still instantiated the whole prototype; that instantiation was removed from it and it has passed since.

## Known gaps

- `docs/20` had no camera-parenting text, so only the pinned-settings line changed.
- The review's J7 (a cosmetic clock for bobs and pulses) was not separately done: the bob and pulse run from the physics tick on `SimClock`, which already pauses with the game.
- Elements already tweened (announcer, hit squash on enemies, HUD punch) were left alone. The enemy hit squash tweens the animator's `scale`; if it smears under interpolation in play, switch it to the sprite child.
- Only the 144 Hz display was measured. 60 Hz is unaffected by construction (one tick per frame, fraction 0 to 1 each frame).
