## docs/19 and Register rules implemented

**Lifecycle** (docs/19 > Tower Console UI > Lifecycle; Register > Interfaces > "Tower Console rules"): 0.3 s dwell below 10% base speed inside the radius AND >= 1 affordable entry; closes on leaving the radius, on Cancel, on player death, on a Level-Up Draft opening; Cancel locks the Console closed until a genuine leave-then-re-enter (edge-detected, not just "not inside"); every other pause reason (pause menu, focus loss, controller disconnect, debug) hides the Console and makes it input-dead without resetting its open/dwell state, so it reappears exactly as it was once that reason clears. All timers are absolute `SimClock.now` snapshots compared with `>=`, never `_process`-delta accumulators, matching `tower_health.gd`'s shield-regen and `player.gd`'s input-buffer conventions.

**Non-pause guarantee**: the Console's own `process_mode` is `PROCESS_MODE_ALWAYS` (the one deliberate exception to this project's `PROCESS_MODE_PAUSABLE` norm, named in the file's own header so a future reviewer does not "fix" it back). It never calls `PauseAuthority.push_reason()`/`pop_reason()`/either immediate variant anywhere (grepped) - it only listens to `reasons_changed` to hide itself and go input-dead.

**Contents** (docs/19 > Contents; Register > "Console price", C-FALLBACK-CONSOLE): the fixed 7-entry catalogue (Repair, Rapid Fire, Heavy Rounds, Patch Kit, Caliber, Optics, Shield Matrix) with price/"Rank n of 3"/"MAX", unaffordable entries greyed and never hidden; Overdrive/Reinforce fallback entries appended to the catalogue once their pool is exhausted, at the flat 90-Scrap price `UpgradeSystem.get_console_cost()` already returns for a `has_max_rank == false` definition.

**Repair (C-REPAIR)**: `heal = min(50, floor(missing/2)*2, scrap_held * (health_restored/scrap_cost))`, cost `= heal / (health_restored/scrap_cost)`, affordable only when missing >= 2 AND scrap_held >= 1 AND heal > 0; the 1:2 ratio is read live from `TowerDefinition.repair_price` (never hardcoded), the "50" ceiling is a named constant citing the Register row (no dedicated schema field carries it, same pattern as this file's own `CONSOLE_Z_INDEX`).

**Purchases**: every purchase (catalogue or sector) is a single unified "channel" state machine - 0.5 s for a catalogue entry, 1.0 s for a sector - that cancels without charge the instant speed exceeds 10% of base, and charges Scrap only on a fresh re-check at completion, only after `UpgradeSystem.apply_rank()` (or the Repair heal-write) actually succeeds, exactly once.

**Auto-fire (C-AUTOFIRE)**: `AutoWeapon.set_auto_fire_suppressed()` is driven every tick from `TowerInteractionRadius.is_player_inside()` alone, independent of whether the Console is open, and released the instant the player leaves.

**Input**: `console_cycle_next/prev`, `console_select_1..7`, `confirm`, `console_cancel` - all pre-existing actions, none added. Cycling wraps across the live catalogue (7-9 entries); number keys 1-7 map to the fixed 7 base entries in the documented order and start a channel directly; `confirm` starts a channel for the highlighted entry; `console_cancel` closes with the re-entry lock. Movement (`move_*`) is never read or intercepted.

**Movement-only sectors (C-SECTORS)**: 7 sectors of `360/7` degrees clockwise from north (see "Interpretations" below), same id order as the catalogue's first 7 slots; a sector auto-starts its own 1.0 s channel while the console is open, the player is inside that sector, and slow enough; completing a purchase disarms that sector; any of {moves fast, leaves that sector} re-arms it; a maxed individual upgrade shows inert (no fill, buys nothing) but a sector only converts to selling its pool's fallback once the WHOLE pool (all 3) is exhausted - matching docs/19's distinct rule for sectors versus the catalogue's simple per-entry "MAX". `movement_only_controls_enabled` is a plain `@export var` on `Console`, default `false`, directly settable by whatever menu P2.14 builds.

**Placement** (docs/19 > Placement; Register C-CONSOLE-NODE): world-space `Node2D`, `z_index = 38`, `modulate.a = 0.85`; nearest edge exactly 200 px from the Tower's centre along the bearing opposite the player (exact rectangle-to-ray geometry, not an approximation); the committed placement bearing only updates once the player's raw bearing differs from it by more than 30 degrees (hysteresis, verified both directions); `scale` is set to `GameCamera.get_view_scale()` every frame so a 24 px local font size stays exactly 24 px on screen at every legal view scale (0.9-1.15).

**UI Layout & Dynamic Container Rules**: every entry row is a single `Label` with `autowrap_mode = AUTOWRAP_WORD_SMART`, `text_overrun_behavior = OVERRUN_NO_TRIMMING`, `size_flags_horizontal = SIZE_EXPAND_FILL`, and a `font_size` theme override pinned at 24 px - verified structurally and after a real 30% pseudo-localization expansion in the UI scaling test.

**Differentiation**: same frame-shape/glyph/header-word rule as the Draft - rounded frame + "P" glyph + "PLAYER" header for Player-pool entries (including Overdrive), squared frame + "T" glyph + "TOWER" header for Tower-pool entries and Repair, never colour alone.

## Interpretations (named, not silently resolved)

1. **Sector width**: the Register states "51.4 degrees," a value rounded to one decimal; 7 x 51.4 = 359.8, leaving a 0.2-degree dead zone that would belong to no sector. `console.gd` uses `360.0/7.0` (51.428571...) so the seven sectors exactly tile the full circle with no gap. This is the only place a Register number was not used literally, and it is because the literal value cannot itself close a circle.
2. **Sector phase**: "clockwise from north" is read as the first sector (Repair) spanning `[0, 51.43)` degrees starting AT north, not centred on it. The alternative (centred on north) is equally defensible from the prose alone; the master/docs do not disambiguate further.
3. **Catalogue vs. sector fallback substitution**: the Contents paragraph says fallback cards "appear here" (in the Tab-cyclable catalogue) once a pool is exhausted, read as an ADDITION (7 fixed entries + up to 2 fallback entries appended). The Input paragraph, for sectors specifically, says the pool's three sectors "each sell that pool's fallback card," read as a REPLACEMENT of those three fixed physical slots (since sectors are pinned to 7 positions with no room to add an 8th). These are two different, both textually supported, readings for two different input surfaces; implemented as written rather than forced to match each other.
4. **Auto-fire suppression scope**: docs/19's own "Presentation" paragraph says auto-fire is "disabled while the Console is open"; the Register's "Tower Console rules" row and MASTER_SDLC.md's "Tower Interaction Mechanics" section both say "disabled at ANY speed while overlapping the Interaction Radius" - a strictly broader condition, independent of whether the Console has actually opened yet. Implemented the Register's broader rule (Register wins on conflict), so auto-fire is suppressed from the instant the player's body overlaps the radius, not from the instant the Console opens.
5. **Cross-task write gaps** (RunInventory has no spend method; TowerHealth has no heal/repair command): resolved by writing directly to the public fields those systems already expose (`run_inventory.scrap_current`, `tower.death_state.current_hp`), mirroring this codebase's own established precedent for exactly this situation (`player.gd`'s `heal()` on `death_state.current_hp`; `tower_health.gd`'s own `configure()` on the same field). Named as required seams for `RunInventory.spend_scrap()` and `TowerHealth.repair()` in a future task, not invented here since `src/economy/**` and `src/tower/**` are off limits this session.
6. **Non-draft pause reasons preserve open state**: the Lifecycle rule lists Draft-opening as a CLOSE condition, separately from the general "hidden while any pause reason is active" rule. Read as: Draft specifically forces a real close-and-reset (matching its explicit listing); every other reason (pause menu, focus loss, controller disconnect, debug) only hides/mutes the Console without resetting `_is_open`, so it resumes exactly where it was once that other reason clears. Verified by a dedicated test (`test_console_hidden_while_a_non_draft_pause_reason_is_active_but_stays_open_underneath`).
7. **Console-close cancels any in-progress channel without charge unconditionally** - not separately stated for leave-radius/death/Draft closes (only stated for the speed-exceeds-10% case), but treated the same way for every close condition, since there is no console left to complete a purchase against once closed.

6. **`console.camera_path`** should point at the scene's `GameCamera` instance; left unset, `scale` defaults to `1.0` (safe, but the 24 px text floor will not actually track camera zoom until this is wired).
7. **SimLoop registration**: `console.gd` self-drives via its own `_physics_process()` (default `driven_externally = false`), exactly like `auto_weapon.gd`, `player.gd`, and `wave_director.gd` all still do. The documented step order (step 12, between XP/level-up at step 11 and Wave Director at step 13) is only actually achieved by calling `SimLoop.register(SimLoop.Step.CONSOLE_CHANNEL_COMPLETION, console)` and setting `console.driven_externally = true` in the assembled scene - this task could not do that itself (`scenes/prototype.tscn` and `src/core/sim_loop.gd` are both off limits). Left self-driving, the Console is still fully correct (SimClock-timed, non-pausing) but its tick lands wherever Godot's own scene-tree traversal places it, not guaranteed to match the documented order relative to other systems.
8. **The Movement-only controls setting P2.14 must surface**: `console.movement_only_controls_enabled` (a plain `@export var bool`, default `false`). The pause/settings menu should set this property directly on the live Console instance when the player toggles it; docs/19 also names this as a choice offered on run-end screens, which is P2.14's own scope.
9. **Console open/close events are not recorded anywhere** (see "What I could not implement," item 2) - a future task adding the missing `EventBus` signals should also wire the Console to emit them.
10. **z_index/world placement caution**: the Console's `z_index = 38` only produces the documented draw order (above enemies at 20, below telegraphs at 40) if it is placed as a sibling under the same 2D world root as the Tower/enemies/player, not nested under a `CanvasLayer`.

## Ledger-worthy findings from this session (for the phase LEDGER, not resolved here)

- **Production bug fixed during this task, not just a test convenience**: `UpgradeSystem.get_console_cost()` `push_error()`s for an unknown `upgrade_id` (by design, for a genuine caller mistake). `Console._entry_for_upgrade()` originally called it unconditionally for all 6 ranked ids every tick while building the catalogue/afford-check, which would have spammed the engine error channel in the REAL game the moment any upgrade id was mistyped or a pool intentionally restricted - not merely a test artifact. Fixed by guarding on `get_definition(id) == null` before ever calling `get_console_cost()`/`is_maxed()`. Recorded here since it is a real defect this task's own test-writing exposed and fixed, not invented for test convenience.
- The "1 resources still in use at exit" / orphan-node symptoms seen mid-session were entirely self-inflicted test-authoring bugs (a bare `SimClockScript.new()` - a `Node`, not `RefCounted` - created in `before_test()` without `auto_free()` or tree membership, and one `GameCamera.new()` freed manually instead of via `auto_free()`), fixed before any test file was finalized. Not present in the final state; named here as a carried lesson for whoever writes the next fresh-`SimClock`-per-test suite in this codebase: **`SimClockScript.new()` (and any other bare `Node.new()`) must be wrapped in `auto_free()` even when deliberately never added to a tree**, since `Node` is not reference-counted the way `RefCounted` is.
